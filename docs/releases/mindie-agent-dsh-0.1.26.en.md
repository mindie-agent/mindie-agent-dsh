# mindie-agent-dsh 0.1.26: Great Subtraction, Thin Plugin Boundary, and Install UX Upgrade

[中文](mindie-agent-dsh-0.1.26.md)

- **Great Subtraction**: deleted 26 legacy duplicate runtime modules. `scripts/` now retains only `mindie_launch.py`, `dsh_transcript.py`, and `setup.py`; the Host boundary retains only `paths.cjs`, `host.mjs`, and `host3.mjs`. The six files total `<= 1,200` lines (about 1,100 here). MCP routing, runtime preparation, sharing/update, locking, storage GC, and all seven host adapters delegate to `mindie-harness` (`API_VERSION = 1`), while cold start still verifies the bundled `assets/mindie-harness-seed.pyz` and `seed-lock.json`. Component Git SHAs are unchanged from `0.1.25`.
- **Two default-on MCP surfaces with zero pre-call gates**: `host.mjs` attaches `remote-dev` (exactly 14 native `dsh` tools) and `mindie-tools` (deterministic components + read-only `mindie_doctor` + the 5 `knowledge_*` tools) per session through `scripts/mindie_launch.py --config <dsh.json> mcp <surface>` and `ManagedMCPAdapter("dsh")`, with zero `_meta`, zero `request_nonce`, and zero `context_file`. A failed second attach disposes the first. Every Node `spawn` passes `windowsHide: true`; background work uses `detached: true` only off `win32`.
- **All-Node authorization and summary bridge in `host3.mjs`**: `agent/turn-stopping` reads `mindie-community.json` (`enabled` + `project_roots`) and `mindie-consent.json` (`contribute`/`local-only`) in pure Node before locating `session.v4.jsonl.zstd` or spawning a child; subagents (`delegationDepth > 0`) never capture. The loopback `/summary` endpoint uses a Bearer token and a 512 KiB cap and serves both `mindie-summary-request/1` and `mindie-distill-request/1`; when no agent is `running`, `setTimeout`/`setInterval` (both `unref()`'d) trigger a windowless `update --background`.
- **Deterministic one-command install and dynamic three-question onboarding**: `uv run https://github.com/mindie-agent/mindie-agent/releases/latest/download/install.py --host dsh` warms the runtime and writes `dsh.json`/`dsh.engine.json`. First-run setup asks three `gh`-aware questions (workspace, experience/privacy tier, one-step SSH NPU). `gh` is recommended only for `contribute` and never blocks `local-only`/`read-only`. Finish with the read-only `mindie_doctor` readiness summary and, only when `gh` is logged in and the user agrees, one polite Star line. `SKILL.md` now states the **Non-Blocking Task Continuity Rule**: on any MindIE tool failure, report the concrete error once (reconciling uncertain remote writes first) and continue immediately via native `ssh`/`scp` or local scripts.
- **Tests and release validation**: `tests/` is rebuilt as a fast, isolated contract suite (`conftest.py`, `test_dsh_transcript.py`, `test_dsh_thin_plugin.py`, `test_dsh_host.mjs`) covering seed verification, canonical `dsh.json` vs legacy `config.json` precedence, `backgroundSpawnOptions('win32').detached === false`, the `Stop` fast path and `contribute`/`local-only` authorization parity (preserving explicit `Admission` revocation), the 14 `remote-dev` tools plus a real zero-`_meta` `knowledge_query`, `setup.py init/sharing/release-metadata`, and `/summary` Bearer/512 KiB plus windowless spawn behavior. Every `harness-compatibility.json` `code_paths`/`test_ids` entry resolves to a surviving file and `setup.py release-metadata` validates it before emitting `mindie-plugin-release/1`.
