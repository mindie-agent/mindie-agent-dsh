# mindie-agent-dsh 0.1.22: Storage Lifecycle Governance and Silent Reclamation of Four Legacy Layouts

[中文](mindie-agent-dsh-0.1.22.md)

- **Storage lifecycle governance**: after the Pre-Build update check and after a successful Post-Switch application, the adapter silently reclaims four generations of historical DSH layout—the legacy `dsh/venv`, excess `dsh/runtimes/<key>` plus orphaned `config/dsh/engines/<key>.json`, excess `dsh/update/generations/v*` (including historical `asset.tgz`), excess `update/component-runtimes/*`, and the orphaned `~/.cache/mindie-agent-dsh/uv-cache` (including Windows `%LOCALAPPDATA%\mindie-agent-dsh\Cache\uv-cache`).
- **Hard rollback and live-process protection**: the active `config.json` binding, `update/current.json` `generation` and `previous_generation`, the DSH profile `node_modules/@mindie-agent/dsh` symlink target, live leases/processes, and cross-plugin source roots are always retained; the sole `updater.recover()` rollback target is never reclaimed.
- **No duplicate `.venv` and no redundant tarball**: the merged component runtime `effective["python"]` is reused directly as the candidate setup interpreter, so no second `uv sync` builds another full `.venv` under `runtimes/<key>`; a verified `asset.tgz` is deleted immediately after extraction and `package/package.json` validation. Cold builds use same-volume `<data_home>/.uv-cache` only when the default uv cache crosses filesystems, replacing the old orphaned cache.
- **Bounded logs and shared runtime leases**: `update/launcher.log` and `update/host.log` rotate atomically to `.1` at 2 MiB, retaining only the active file plus `.1`; Windows rename conflicts are tolerated. The knowledge MCP, component MCP, and warm sidecar hold a shared `acquire_runtime_lease` on `owning_dir(sys.executable)` while resident.
- **Component pinning**: `mindie-knowledge 0.13.22`, `mindie-coordinator 0.7.11`, `mindie-debugger 0.1.3`, `mindie-diagnostics 0.5.15`, `mindie-profiler 0.5.15`, `mindie-sim 0.9.15`, and `remote-dev 0.11.12` are pinned to their formal commits, with `uv.lock` and `runtime-requirements.txt` synchronized.
- **Test isolation and gates**: add cross-platform storage lifecycle and Node log rotation regressions; pytest additionally isolates `TMPDIR`/`TEMP`/`TMP` and `UV_CACHE_DIR`; every core `.py`/`.mjs` module (notably `host3.mjs`) remains under 800 lines.
